# MentorHub PRD (제품 요구사항 명세)

## MVP 캡슐

1. 목표: 모든 사람이 선생님이자 학생인 지역 기반 멘토링 플랫폼
2. 페르소나: 특정 취미/관심사를 가진 전 연령층 (지역 주민)
3. 핵심 기능: FEAT-1 멘토링 탐색/검색, FEAT-2 관심사 기반 매칭, FEAT-3 1:1 채팅
4. 성공 지표 (노스스타): 특정 지역에서 활성 사용자 1,000명 돌파
5. 입력 지표: 월간 멘토링 세션 수, 매칭 성사율
6. 비기능 요구: 실시간 채팅 지연 < 1초
7. Out-of-scope: 사람↔커뮤니티 자동 추천 (v2), 화상/온라인 멘토링 (v2)
8. Top 리스크: 초기 사용자 확보 (멘토와 멘티 닭과 달걀 문제)
9. 완화/실험: 특정 지역/대학가 대상 베타 런칭으로 밀도 확보
10. 다음 단계: /screen-spec 실행

---

## 1. 제품 개요

- **서비스명**: MentorHub (멘토허브)
- **핵심 가치**: "모든 사람이 선생님이자 학생" — 상호 멘토링을 통한 지역 커뮤니티 활성화
- **타겟 사용자**: 특정 취미/관심사를 가진 전 연령층 (지역 기반 오프라인 만남 중심)
- **핵심 차별화**: 기존 커뮤니티 앱(밋업, 소모임)과 달리, 쌍방향 멘토링에 집중. 가르치는 것과 배우는 것을 동시에 설정하여 상호 학습 관계 형성

---

## 2. 핵심 기능

### FEAT-1: 멘토링 탐색/검색
- **설명**: 카테고리별(음악, 운동, 요리, 프로그래밍 등)로 멘토를 탐색하고 검색
- **Why**: 사용자가 부담 없이 둘러보다가 마음에 드는 멘토를 발견할 수 있도록
- **우선순위**: MVP 필수
- **주요 동작**:
  - 홈 화면에서 카테고리별 탐색
  - 카테고리 클릭 시 해당 분야 멘토 목록 표시
  - 멘토 클릭 시 멘토링 상세 정보 (시간, 장소, 내용) 확인

### FEAT-2: 관심사 기반 사람↔사람 매칭
- **설명**: "가르칠 수 있는 것"과 "배우고 싶은 것"을 기반으로 적합한 멘토/멘티를 알림으로 추천
- **Why**: 새로운 방식의 소통 — 서로 가르치고 배우는 관계를 만들기 위해
- **우선순위**: MVP 필수
- **주요 동작**:
  - 온보딩 시 관심사 설정 (가르칠 것 + 배울 것)
  - 매칭 알고리즘이 적합한 사람을 찾아 알림 발송
  - 매칭 탭에서 추천 결과 확인 가능

### FEAT-3: 1:1 채팅
- **설명**: 매칭된 사람과 앱 내에서 1:1 실시간 채팅으로 멘토링 약속 잡기 및 소통
- **Why**: 멘토링 만남을 조율하고 관계를 이어가기 위한 소통 공간
- **우선순위**: MVP 필수
- **주요 동작**:
  - 멘토링 신청 또는 매칭 후 채팅방 자동 생성
  - 실시간 1:1 메시지 전송/수신
  - 채팅 목록에서 진행 중인 대화 관리

---

## 3. 사용자 스토리

### 멘토(가르치는 사람) 관점
- As a 기타를 잘 치는 직장인, I want 내 동네에서 기타 배우고 싶은 사람을 찾아 가르치고 싶다, so that 내 지식을 나누고 보람을 느낄 수 있다.

### 멘티(배우는 사람) 관점
- As a 요리를 배우고 싶은 대학생, I want 근처에 요리를 잘하는 멘토를 찾고 싶다, so that 실제로 만나서 요리를 배울 수 있다.

### 쌍방향 멘토링 관점
- As a 엑셀을 가르칠 수 있고 기타를 배우고 싶은 사람, I want 기타를 가르칠 수 있고 엑셀을 배우고 싶은 사람과 매칭되고 싶다, so that 서로 지식을 교환할 수 있다.

## 4. 제약 조건

- **시간**: 미정 (MVP 우선 개발)
- **예산**: 무료 서비스로 시작 (Supabase 무료 티어 + Vercel 무료 배포)
- **인력**: 1인 개발 (AI 보조)
- **지역 범위**: 특정 지역에서 베타 시작 후 확장

---

## 5. MVP 범위

### Phase 0 (MVP) — 포함
- 회원가입/로그인 (소셜 로그인)
- 온보딩 (관심사 설정: 가르칠 것 + 배울 것)
- 카테고리별 멘토링 탐색
- 멘토링 상세 페이지
- 관심사 기반 사람↔사람 매칭 (알림)
- 1:1 실시간 채팅
- 프로필 (가르칠 수 있는 것 + 배우고 싶은 것)

### Phase 1 (v2) — 제외
- 사람↔커뮤니티 자동 추천
- 온라인/화상 멘토링
- 멘토링 후기/평점 시스템
- 멘토링 일정 관리 (캘린더)
- 결제/유료 멘토링

## 6. 벤치마킹 분석

| 서비스 | 특징 | 성공/실패 요인 | MentorHub와의 차이 |
|--------|------|---------------|-------------------|
| 밋업(Meetup) | 그룹 활동 기반, 오프라인 모임 | 성공: 오프라인 만남. 약점: 1:1 멘토링 부재, 일방향 | MentorHub는 1:1 쌍방향 멘토링에 집중 |
| 소모임 | 관심사 기반 소규모 모임 | 성공: 한국 시장 특화. 약점: 멘토링보다는 친목 중심 | MentorHub는 지식 교환이 핵심 가치 |
| 네이버 카페 | 커뮤니티 게시판 | 성공: 트래픽. 약점: 오프라인 연결 약함, 구식 UI | MentorHub는 지역+오프라인+매칭 통합 |
| 탈잉/클래스101 | 유료 강의 플랫폼 | 성공: 수익 모델. 약점: 상호 학습 아닌 일방향, 유료 | MentorHub는 무료 상호 멘토링 |

**우리의 차별점**: "가르칠 것 + 배울 것"을 동시에 설정하는 쌍방향 구조. 기존 서비스는 모두 멘토/강사가 고정된 일방향 구조.

## 7. 가설 vs 사실

| 항목 | 분류 | 내용 | 검증 방법 |
|------|------|------|----------|
| 사람들이 자신의 지식을 무료로 나누고 싶어한다 | 가설 | 보상 없이도 멘토링 의지가 있을 것 | 베타 유저 인터뷰 (5명 이상) |
| 지역 기반 오프라인 만남에 수요가 있다 | 가설 | 온라인보다 오프라인 선호 | 설문조사 + 베타 테스트 |
| 쌍방향 매칭이 단방향보다 매력적이다 | 가설 | "가르치면서 배우기"가 동기 부여 | A/B 테스트 (쌍방향 vs 단방향 프로필) |
| 카테고리별 탐색이 직관적이다 | 사실 | 대부분의 앱이 카테고리 구조 사용 | 기존 UX 패턴 검증 완료 |
| 실시간 채팅이 약속 잡기에 필수다 | 사실 | 당근마켓 등 검증된 패턴 | 기존 서비스 사례 |

## 8. 타협 기록

| 원래 계획 | 현재 계획 | 타협 이유 | 복구 계획 |
|----------|----------|----------|----------|
| 사람↔사람 + 사람↔커뮤니티 매칭 | 사람↔사람 매칭만 | MVP 범위 축소 | v2에서 커뮤니티 추천 추가 |
| 온/오프라인 멘토링 | 오프라인만 | 핵심 차별화 집중 | v2에서 화상 멘토링 추가 |
| 전국 서비스 | 특정 지역 베타 | 사용자 밀도 확보 우선 | 베타 성공 후 지역 확장 |

## 9. 실패 대응

- **MVP 정의**: 카테고리 탐색 + 매칭 + 채팅이 동작하는 최소 버전
- **실패 시나리오**: 사용자가 멘토로 등록하지만 멘티가 부족 (또는 반대)
- **학습 목표**: 실패해도 "사람들이 무료 멘토링에 관심이 있는지"를 검증
- **Pivot 옵션**:
  1. 유료 멘토링 플랫폼으로 전환
  2. 특정 분야(코딩, 외국어)에 집중
  3. 온라인 멘토링으로 범위 확대
